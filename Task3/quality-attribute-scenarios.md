# Quality Attribute Scenarios

Формат сценария (6 полей): Источник → Стимул → Окружение → Артефакт → Отклик → Мера отклика.

| # | Атрибут | Источник | Стимул | Окружение | Артефакт | Отклик | Мера отклика |
|---|---|---|---|---|---|---|---|
| QAS-01 | Доступность | Покупатель | Открывает карточку товара в пик запуска | Нормальная работа, пиковая нагрузка | Сервис каталога | Система возвращает карточку без ошибок | 99,9% успешных ответов за 30 дней |
| QAS-02 | Задержка P99 | Покупатель | Запрашивает первый товар на главном экране | Мобильная сеть 3G/4G, пик | API каталога + CDN | Товар отображается быстро | P99 < 2 секунды |
| QAS-03 | Пропускная способность | Рекламная кампания | Всплеск регистраций и заказов в день запуска | День запуска 15 октября | API Gateway + сервис заказов | Система держит нагрузку без деградации | ≥ 500 RPS, без 5xx-лавины |
| QAS-04 | Восстановление (RTO) | Отказ дата-центра | Потеря основного региона (например, сбой провайдера) | Отказ региона | Платформа целиком | Переключение на резервный регион | RTO ≤ 4 часа |
| QAS-05 | Восстановление (RPO) | Сбой базы данных | Потеря последних транзакций из-за отказа БД | Отказ первичной БД | PostgreSQL + реплика | Восстановление из реплики/бэкапа | RPO ≤ 15 минут |
| QAS-06 | Устойчивость | Платёжный провайдер M-Pesa | M-Pesa отвечает таймаутами/ошибками | Пиковая нагрузка | Сервис оплаты | Circuit Breaker размыкается, заказы не теряются, уведомление дежурному | Деградация только оплаты M-Pesa, остальные способы работают |
