# Стратегия наблюдаемости

Схема сбора телеметрии — `observability.puml` / `observability.png`. Ниже — что и как наблюдаем.

## Четыре золотых сигнала

| Сигнал | Для каталога | Для оплаты | Для уведомлений |
|---|---|---|---|
| Задержка (latency) | P99 ответа API | P99 инициализации платежа | P99 отправки уведомления |
| Трафик (traffic) | RPS на `/catalog`, `/search` | Попыток оплаты/мин | Отправок SMS/push в сек |
| Ошибки (errors) | Доля 5xx | Доля сбоев инициализации | Доля failed delivery |
| Насыщение (saturation) | Загрузка CPU, пул соединений БД | Очередь на сверку, лимиты провайдера | Очередь отправки, лимиты шлюза |

## Метрики

- RED (Rate, Errors, Duration) — на каждый сервис и endpoint.
- USE (Utilization, Saturation, Errors) — на ноды, БД, Redis, очереди.
- Бизнес-метрики: регистрации, заказы, выручка (для live-дашборда инвестора, артефакт 2).

## Логи

Структурированные JSON-логи со `trace_id` и `order_id`. Уровни: info/warn/error. Централизованный сбор в Loki, хранение 30 дней (горячие — 7 дней). Красные флаги — по паттернам ошибок платежей и 5xx.

## Распределённая трассировка

OpenTelemetry сквозь API Gateway → сервисы → БД/внешние вызовы. Каждая операция пользователя (заказ, оплата) — это один трейс. Это позволяет отличить «наш сервис упал» от «M-Pesa таймаутит».

## Инструменты

| Задача | Инструмент |
|---|---|
| Сбор телеметрии | OpenTelemetry SDK/агенты |
| Метрики | Prometheus |
| Дашборды | Grafana |
| Логи | Loki |
| Трейсинг | Jaeger |
| Алерты | Alertmanager → дежурному |

## Связь метрик с SLI

- SLI «доступность каталога» = `sum(rate(http_requests_total{status!~"5.."}[30d])) / sum(rate(http_requests_total[30d]))` (Prometheus).
- SLI «задержка P99» = `histogram_quantile(0.99, http_request_duration_seconds_bucket)`.
- SLI «успешность оплаты» = `payment_init_success / payment_init_total`.

Эти же выражения используются в алертах: при исчерпании бюджета ошибок (доступность ниже SLO) автоматически создаётся инцидент.

## Что считается инцидентом

- Доступность каталога/оплаты ниже SLO (исчерпан бюджет ошибок).
- Полный отказ платёжного провайдера (не отдельный decline, а системный сбой).
- Массовая недоставка уведомлений.
- Любой простой, грозящий потерей денег или данных.
