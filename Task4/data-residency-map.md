## 2. Движение данных между странами (что и через что проходит)

Общий API Gateway (в af-south-1) принимает только обезличенный запросный контекст, а не персональные данные нигерийцев. Разделяем два типа трафика:

1. Управляющий трафик (routing/auth), но не данные. Для нигерийского покупателя шлюз принимает запрос, проверяет токен, но персональные данные (профиль, финансовые, заказ) не реплицируются и не оседают в ЮАР — они живут только в локальном нигерийском хранилище. Через шлюз в ЮАР проходят только технические поля: `session_token`, `request_id`, `trace_id`, id-каталога. Каталог (товары, цены) — это публичные данные, не персональные, их можно обслуживать из общего региона.

2. Данные нигерийцев обслуживает нигерийский регион. Сервисы нигерийского трафика (`ngsvc` + `ngdb`) держат профиль и заказ локально. Шлюз лишь проксирует запрос к ним, не складывая копию.

Где лежат копии:

- Нигерийские персональные данные — только внутри Нигерии, реплика для DR тоже внутри страны (другой ЦОД/зона того же или резервного локального провайдера). За границу не выносятся.
- Кенийские профили — первичная копия в af-south-1 + serving-копия в Кении (требование KICA о хранении копии в юрисдикции).
- Южноафриканские — af-south-1 (это и есть территория ЮАР).
- Логи IAM/аудита — af-south-1, но это вспомогательный технический журнал, без персональных данных в открытом виде.

Что останется в стране при отказе региона:

- При отказе af-south-1 (ЮАР): кенийская serving-копия в Кении и нигерийское хранилище в Нигерии не затрагиваются — покупатели Кении и Нигерии продолжают обслуживаться локально, теряется только обслуживание ЮАР до переключения на standby.
- При отказе нигерийского провайдера: нигерийские персональные данные не могут быть временно вынесены за границу без подтверждения юриста; включаем режим деградации (приём заказов с минимумом полей) пока локальный провайдер не восстановится либо не будет включён резервный локальный ЦОД.

## 3. Принципы

1. Нигерийские персональные данные — только в Нигерии. У AWS/Google/Microsoft нет региона в Нигерии, поэтому используем локального провайдера. Это консервативное допущение до заключения юриста (артефакт 3).
2. Псевдонимизация не отменяет локализацию до письменного подтверждения юриста. Для Нигерии псевдонимизированные заказы пока держим тоже в стране — это консервативный выбор, который мы сможем ослабить, если юрист разрешит вынос.
3. Шифрование — мера поверх локализации, а не её замена.
4. Обратимость: граница данных задана policy, а не кодом, чтобы после ответа юриста перенести категорию данных без переписывания (ADR-003).
5. Общий шлюз не хранит персональные данные — он маршрутизирует, а данные субъекта живут в его регионе.
