# Data Residency Map — Africa Delivery

Карта размещения данных по трём странам. Построена по шаблону Data Residency Map.

| Категория данных | Страна субъекта | Где хранится | Где обрабатывается | Правовое основание | Техническая мера |
|---|---|---|---|---|---|
| Персональные данные покупателя (имя, телефон, email, адрес) | Нигерия | Локальный нигерийский провайдер | Нигерия | NDPR: хранение в стране | AES-256, ключи у нас (CMK), маскирование телефона |
| Персональные данные покупателя | ЮАР | AWS af-south-1 (Кейптаун) | ЮАР | POPIA: согласие, обработка в стране | Шифрование, подтверждаемое согласие |
| Персональные данные покупателя | Кения | AWS af-south-1 / GCP africa-south1 | Кения/регион | DPA 2019 / KICA | Локальная serving-копия, шифрование |
| Финансовые/транзакционные данные | Нигерия | Локальный нигерийский провайдер | Нигерия | NDPR + нормы CBN | Токенизация карт, маскирование, шифрование |
| Платёжные данные (платёж-adjacent) | Кения | Кения (локальная копия) | Кения | DPA 2019 / KICA — строже, чем общие данные | Токенизация, минимальное хранение |
| Данные заказов (псевдонимизированные) | Все три | Регион субъекта (или af-south-1 при псевдонимизации) | Регион субъекта | NDPR/POPIA/DPA — псевдонимизация вне scope (уточнить у юриста) | Псевдонимизация, агрегация |
| Записи согласий (consent) | Все три | В регионе субъекта | Регион субъекта | POPIA (обязательно), NDPR | Неизменяемый журнал consent |
| Логи IAM/аудита | Все три | af-south-1 (аудит-бакет) | af-south-1 | Общие требования безопасности | Envelope encryption, read-only |

## Принципы

1. Нигерийские персональные данные — только в Нигерии. У AWS/Google/Microsoft нет региона в Нигерии, поэтому используем локального провайдера. Это консервативное допущение, принятое до заключения юриста (артефакт 3).
2. ЮАР и Кения — размещаем в африканских регионах глобальных провайдеров (af-south-1 / africa-south1), это покрывает требования локализации.
3. Шифрование не отменяет локализацию — это техническая мера поверх, а не замена требования о хранении в стране (типичная ошибка, которую мы не допускаем).
4. Обратимость: граница данных спроектирована так, чтобы при уточнении требований юристом через 4–6 недель перенести категорию данных без переписывания системы (ADR-003).
