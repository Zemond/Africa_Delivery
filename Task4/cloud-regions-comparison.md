# Сравнение cloud-регионов

Цель — выбрать регионы для ЮАР/Кении (глобальные провайдеры) и локального провайдера для Нигерии (где глобальных регионов нет).

| Провайдер / регион | Доступные сервисы | Latency до целевых стран | Цена (отн. US-East) | SLA | Вывод |
|---|---|---|---|---|---|
| AWS af-south-1 (Кейптаун, ЮАР) | EC2, RDS, S3, EKS, CloudFront, KMS — широкий набор | Лагос ~110–130 мс, Найроби ~70–90 мс, Йоханнесбург ~10 мс | +10–15% к US-East | EC2 99,99%, S3 99,9% | Основной регион для ЮАР и Кении |
| Google africa-south1 (Йоханнесбург, ЮАР) | Compute Engine, Cloud SQL, GCS, GKE, Cloud KMS — полный набор | Лагос ~120 мс, Найроби ~80 мс, Йоханнесбург ~5 мс | ~на уровне US, местами дешевле | Compute 99,99%, GCS 99,9% | Альтернатива/резерв для ЮАР и Кении |
| Azure South Africa North (Йоханнесбург) | VMs, SQL DB, Blob, AKS — хороший, но чуть уже набор | Лагос ~130 мс, Найроби ~90 мс | +10–15% | VM 99,99% | Запасной вариант |
| Локальный нигерийский провайдер (например, MainOne / Medallion / Rack Centre) | Ограниченный набор managed-сервисов (IaaS, managed DB — не везде) | Лагос ~5–10 мс (лучший для Нигерии) | Выше за единицу, помесячная оплата | Обычно 99,9% и ниже, без жёстких гарантий | Обязателен для NDPR — нигерийские персональные данные только здесь |

## Ключевой вывод

Для Нигерии выбора нет: NDPR требует хранения в стране, а у AWS/Google/Microsoft нет нигерийского региона — значит, берём локального провайдера, несмотря на худший SLA и меньший набор сервисов. Для ЮАР и Кении оптимален AWS af-south-1 (широкий набор сервисов, приемлемая задержка, понятный SLA); GCP africa-south1 держим как резервный регион для мультиоблачной обратимости. Полное обоснование — в ADR-003.
